## Added

### CX-18 — §6.5 perf fixture in-repo + manual CI `perf` channel

- `tests/performance/paired-compaction-benchmark.mjs` formalizes the §6.5
  protocol: a pretrimmed 60-message fixture, A=legacy / B=three-section+record
  run in **alternating paired rounds (10)**, `process.cpuUsage` sampling,
  median aggregation, `--json` output and a `GITHUB_STEP_SUMMARY` markdown
  table. No `.test.` suffix → **not collected by vitest**.
- `ci.yml` gains a **`perf` job** that runs **only on `workflow_dispatch`** —
  the push / PR gate does **not** grow. The job builds and runs the benchmark,
  posting numbers to the job summary.
- **First dispatch** (run `37574041315`, ubuntu, load 0.78):
  A legacy **2.1809 ms/op** vs B three-section+record **2.3511 ms/op**
  → **median delta 6.00%** (budget <2% → **OVER**).

### OBS-F — `release-notes/` tracked; the CX-15 two-state body is live

- A top-level `release-notes/` (with `README.md`) is now committed and
  **intentionally not ignored** — `docs/` is fully gitignored, so the old
  `docs/releases/<tag>.md` convention could never reach CI.
- The CX-15 two-state path was migrated `docs/releases/<tag>.md` →
  **`release-notes/<tag>.md`** (script + unit test updated, 5/5 green).
- From this release on, the RELEASE stage drops `<tag>.md` in the bump commit
  and CI publishes the full body via the **`--notes-file`** branch. This file
  is that artifact for v6.12.0.

## Notes

### CX-19 — persistence write-path probe (probe only; no code change)

`tests/performance/persist-write-exp.mjs` measures three implementations
(line 325 B, n=5000, reps=5):

| impl | µs/op | vs current |
|------|:-----:|:----------:|
| A `appendFileSync` per record (current) | 121.6 – 127.2 | — |
| B fd reuse (open once + `writeSync`) | 13.8 – 15.2 | **−88.0% – −88.7%** |
| C buffered ×64 | 2.2 – 2.8 | −97.8% – −98.3% |

Corroborated by three independent measurements: Edith 3 rounds
(−88.1 / −88.7 / −88.0%), Friday local (139.5 → 15.3 µs, −89%), Jarvis on CI
(133 → 14 µs, −89%). Attribution: the fixed cost is per-call **open + close**,
not fs throughput, and is load-independent — the CI delta of 6% × 2.18 ms
≈ **130 µs/record** matches impl A's 133 µs/record exactly.
