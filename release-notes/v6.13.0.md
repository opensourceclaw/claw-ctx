# claw-ctx v6.13.0 — Stage-Progress Trigger, Continuation Guard, OBS-3 Fix

> **Scope**: P1 stage-progress trigger and P3 continuation guard ship
> **default off** — untoggled, compaction output is byte-identical to
> v6.11.x (`summary-three-section` golden, v6.10.4 fixture, 14 passed).
> `ctx_compact` / `ctx_build` / `ctx_inject` signatures unchanged, zero new
> dependencies. Also in this release: the OBS-3 screening fix and per-repo
> stage-gate slots (CX-20).

## Added

### P1 — stage-progress trigger (`StageProgressTrigger`)

- Boundary-weighted compaction threshold: a host-supplied stage transition
  (non-empty A→B) marks a safe compaction point; `adjustThreshold` discounts
  the threshold for that evaluation only.
- **Pinned same-turn expiry**: a boundary that missed the `minTokens` floor
  is **consumed** — it does not discount mid-next-stage. A boundary is never
  banked.
- Single re-calibration surface (reserved for the v6.14.0 W3 backfill);
  first observation and empty stages never form a boundary.

### P3 — continuation guard (`ContinuationGuard`)

- Post-compaction window guard with three **pure** base detectors:
  `redo-loop` (same tool + identical args twice), `refetch-summarized`
  (retrieval tool re-reading content that a summary already carries),
  `plan-restatement` (assistant re-states the `Next Action:` block).
- **Warn-only sidecar** — it never blocks or mutates compaction.
- `detectors[]` constructor argument is the **v6.14.0 W4 extension slot**
  (injected detectors take effect immediately); single-pass parse memo;
  `windowTurns` expiry auto-disarms the guard.

### CI `perf` channel gains the P1/P3 harness

- `tests/performance/p13-paired-overhead-benchmark.mjs` joins the **manual**
  `perf` job (`workflow_dispatch` only — the push / PR gate does not grow).
  It pairs A=existing / Boff=default / Bon=armed with `process.cpuUsage`
  sampling, reports a noise floor and the amortized figure, and writes a
  markdown table to the job summary.

### CX-20 — per-repo `gates.json` slots

- `.githooks/pre-push` now reads `~/.openclaw/gates/<repo>.json`; the legacy
  shared `gates.json` remains as a read fallback with a migration note, and
  `OPENCLAW_GATES_FILE` still wins explicitly. `scripts/migrate-gates.sh`
  splits existing slots.
- Fixes the real 2026-10-07 incident where two concurrent repo releases
  clobbered each other's `release-approval-gate` record in the single shared
  slot (fail-closed, no production damage — but a genuine release hazard).

## Fixed

### OBS-3 — one screening definition (`stripSummaryScaffold`)

The legacy summary tail `[Compacted History …] Continue with the current
task …` matched the `continue` keyword and produced a **structural
missingNext false-negative** (it counted as present 0% of the time). Fixed
scaffolding — author-controlled text only — is now stripped before keyword
screening, and **P4 metrics and the P3 detectors share that single
definition**.

| fixture | expected | measured |
|---------|----------|:--------:|
| legacy tail `… Continue with the current task` | counted as missing | **100%** (was 0%) |
| three-section headers with **empty** values | counted as missing | **100%** |
| three-section with real `Next Action:` value | not counted | **0%** |
| user content containing `continue` | not stripped (matches) | **0%** |

## Notes

### Performance — CI is the authority

Run `37898544346` (`workflow_dispatch`, clean ubuntu runner, loadavg 1.44):

| variant | reading | verdict |
|---------|---------|:-------:|
| **Boff default (shipping state)** | 2.2205 ms/op, **vs A −0.21%** | **PASS** |
| Bon armed (worst case) | 2.2914 ms/op, vs Boff +4.75% | raw OVER, **< 6.46% noise floor** (indistinguishable) |
| **amortized(on)** | **0.29% ≪ 2% budget** | **PASS** |

The guard only acts inside the `windowTurns=3` post-compaction window, so the
shipping state costs nothing and the armed cost amortizes far under budget.
Edith deliberately declined to judge this from a shared dev machine (local
noise floor 3.29% > the 2.54% default-state signal) and asked for a CI
dispatch — the CI reading above is that anchor.

**Reported as-is (§6.5 legacy baseline)**: the same run reads the older §6.5
baseline at **4.53% vs the <2% budget (OVER)**. That cost belongs to the
existing v6.11/v6.12 three-section behavior and **is unrelated to this
batch**; whether "2% budget" is a hard gate is a separate governance
question with Peter.
