# claw-ctx v6.13.1 — Approval Record Canonical Dir + Audit No-Op

> **Scope**: pre-push / audit hardening only. **No product behavior change** —
> `src/` untouched, zero new dependencies, `ctx_compact` / `ctx_build` /
> `ctx_inject` signatures unchanged.

## Fixed

### Approval records live in `inbox/inbox-release/` — one canonical directory

The pre-push gate's second requirement (a Peter release approval) previously
scanned **both** `inbox/inbox-plan/` and `inbox/inbox-release/`. Per the
2026-10-09 ruling that wide scan was a bug: an approval is a RELEASE artifact,
and every v6.10.3–v6.12.0 precedent already lived in `inbox/inbox-release/`.
The scan is now **`inbox/inbox-release/` only**.

- An approval that drifted into `inbox-plan/` is now **rejected** (fail-closed).
- CX-4 / CX-14 dual-claim protection is untouched: a receipt must still carry
  the TEST signature and an approval must not, so no single file can satisfy
  both requirements.
- Batch-window semantics are unchanged (a record must post-date the oldest
  commit in the push window).

### Audit no-op when there is nothing to push

`tools/audit-stage-gate.sh --mode=client` is also used for forensics. Re-running
it **after** a successful push (local == remote) used to degrade the batch
window to `wstart=0`, which re-surfaced v6.11/v6.12-era pre-policy gaps
(`friday-design-review-cx16-tailbatch-*` Refs, three tail-batch handoff tasks)
as a spurious red. The script now mirrors the real hook — which `continue`s on
`local == remote` and therefore never evaluates that case — and exits **rc=0**
with `stage-gate no-op (nothing to push)`.

This closes Karen's release observation 3 from the v6.13.0 release receipt.
