# claw-ctx v6.14.0 — Reset-Boundary Continuity Handoff

> **Scope**: a new reset-handoff capability plus follow-up fixes for identifier
> capture, truncation direction, and load-induced performance false reds.
> `ctx_compact` / `ctx_build` / `ctx_inject` signatures are unchanged, and all
> new handoff fields are additive.

## The Problem

OpenClaw's daily session reset truncates the live window, and no
post-reset re-injection existed because this path never runs compaction. After
a daily reset or cold restart, assembled context could therefore start with an
empty `[Session History]` even though the previous session had substantial work
in flight.

## Added

### Reset-boundary continuity handoff

The host `before_reset` hook now captures a session summary before the window
is discarded. On cold-start `assemble()`, claw-ctx lazily bootstraps resume
history from that summary, so `[Session History]` is non-empty after a reset or
restart. The bootstrap runs at most once per cold start.

### Handoff identifier ledger

The handoff payload now carries additive continuity evidence:

- pending files and identifiers, capped at 20 each, matched through
  `task-` / `pipeline-` / `回执-` / `receipt-` prefixes and file-extension
  tokens;
- the last three user messages, capped at 300 characters each.

All three reinjection paths — full history, compact history, and the default
context assembler — render the same `Open items:` view. Payloads produced
before v6.14.0 render unchanged.

## Fixed

### Most-recent-first identifier capture

Identifier extraction now scans newest-first, so the 20-item cap preserves the
latest work rather than the oldest. A shared `openItemsOf()` helper performs
cross-type exact deduplication and suffix absorption, keeping the longest form
when one file path is the suffix of another.

### Perf false reds under load

All eight performance describes now run sequentially, and latency thresholds
carry a 3× margin over measured peaks. No retry, skip, or soft assertion was
added: a controlled threshold-to-zero experiment confirms that real regressions
still fail the suite.

### Workspace hygiene

The runtime `MEMORY.md` template is now gitignored; release work does not carry
session memory into the repository.

- Five consecutive green full runs across the implementation and acceptance

- `npm run build` clean; both `tsc --noEmit` configurations report 0 errors.
- `audit-stage-gate.sh --mode=repo` exits 0.

## Security Note

The runtime dependency surface is unchanged: `js-tiktoken` is the only
production dependency. A full `npm audit` currently reports 25 advisories in
dev-only tooling chains (`openclaw`, `vitest`, `eslint`, `typedoc`); none of
those packages are included in the published package. `npm audit --omit=dev`
could not complete because npm's quick-audit endpoint is retired, so this
release does not claim a zero-vulnerability result.

## Known Boundaries

- The captured summary is topic-level; identifiers can still be dropped.
- Live daily-reset verification still requires a gateway restart; the hook path
  itself is covered by unit and replay tests.
- Identifier matching covers prefix-shaped tokens only; tokens inside a single
  message retain their natural order.
- The 3× threshold leaves 2–3× performance regressions below the assertion
  boundary. This trade-off is recorded deliberately.

## Upgrade Notes

No configuration or migration is required. Existing handoff payloads remain
valid: absent fields are omitted rather than rendered as empty `Open items:`.
