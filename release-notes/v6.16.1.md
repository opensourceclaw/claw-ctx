# claw-ctx v6.16.1 — Postinstall Hook Safety Fix

> **Scope**: patch release. Fixes a packaging defect introduced in v6.16.0 where installing this package as a dependency could rewrite the consumer repository's `core.hooksPath`, silently disabling the consumer's own git hooks. No engine API or behavior changes.

## Fixed

### postinstall no longer touches consumer repositories

In v6.16.0, `postinstall` ran `git config core.hooksPath .githooks`. npm executes dependency lifecycle scripts with the working directory inside the consumer repository (`node_modules/@opensourceclaw/claw-ctx`), so that command wrote the **consumer's** `.git/config` — replacing that repository's hook path with `.githooks` (usually nonexistent) and silently disabling its gates. Affected repositories observed in the field: the claw-mem and devclaw repositories; both were restored to their maintained `scripts/git-hooks` path.

v6.16.1 replaces the lifecycle script with `scripts/postinstall-hooks.mjs`:

- it resolves the git top-level; when the working directory is not the repository root (dependency install) or is not inside a git checkout, it exits 0 without side effects;
- only a maintainer checkout (working directory equals the repository root) wires `core.hooksPath = .githooks`, and it writes with `--local`;
- the script is zero-dependency and is included in the published tarball (`files` whitelist).

## Tests

- New `tests/unit/postinstall-hooks.test.ts` with four cases: a consumer's existing `core.hooksPath` is preserved, an unset consumer value stays unset, a maintainer checkout is wired to `.githooks`, and a non-git directory is a silent no-op.
- Full suite: **124** files / **1506** passed / **5** skipped / **0** failed.
- `tsc --noEmit`: 0 errors. `npm run build`: clean. `npm pack --dry-run` includes `scripts/postinstall-hooks.mjs`.

## Upgrade Notes

- If you installed claw-ctx **6.16.0** as a dependency, check the installed repository's local hook path: `git config --local core.hooksPath`. If it was changed to `.githooks`, restore your previous value (for example `git config core.hooksPath scripts/git-hooks`), then verify your pre-push gates run again.
- No configuration or API migration is required for this patch.
