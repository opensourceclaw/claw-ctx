# claw-ctx v6.13.3 — MCP SDK Floor Override + Shim-Case Strengthening

> **Scope**: dependency floor + test-strength only. **Runtime behavior
> unchanged** — the runtime `dependencies` (`js-tiktoken`) are untouched, and
> `ctx_compact` / `ctx_build` / `ctx_inject` signatures are unchanged.

## Fixed

### `@modelcontextprotocol/sdk` pinned to a patched floor (dependabot #64, HIGH)

GHSA-6qxp-vccf-f47h: the MCP TypeScript SDK's OAuth client could send
credentials to an authorization server chosen by the MCP server. Affected
range: `1.12.0 – 1.30.1`.

In this repository the vulnerable version was reachable **only through
dev-domain transitive chains** (`openclaw` / `@earendil-works/pi-agent-core`
→ `@google/genai` → `sdk@1.30.0`). The runtime `dependencies` are just
`js-tiktoken`, so `npm audit --omit=dev` already reported **0** before the fix.

The fix is a **floor override — not a ceiling lock**:

```json
"overrides": {
  "@modelcontextprotocol/sdk": ">=1.31.0"
}
```

A deterministic lockfile regeneration resolves all four resolution points to
**`1.32.1`** (deduped / overridden, no escape path). `npm audit` now reports
**0** vulnerabilities, and no runtime dependency changed.

### The stale-receipts shim case is now discriminating (OBS-V6132-1)

The v6.13.2 case `faithful GNU shim — stale receipts still rejected` passed
even on the **old** (unfixed) `mtime_of`: the pre-fix code rejected through the
shell's integer-error path, which happened to produce the same rejection
reason — so the assertion had no discriminating power. The case keeps its
original assertion and adds one that only holds after the fix:

```ts
expect(r.out).not.toContain("integer expression expected");
```

Revert-and-restore proof: reverting `mtime_of` to the old BSD-first form turns
the case red and reproduces `integer expression expected`; restoring the fix
returns it to green.
