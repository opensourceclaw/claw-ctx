# claw-ctx v6.16.0 — Cost Ledger, Durable Turn Commits, Release Guards

> **Scope**: a read-only cost/cache annotation ledger with a `claw-ctx cost` CLI, a persisted usage fallback, declared transcript semantics with an idempotent `commitTurn`, and hardened release and gate rules. No breaking changes: `ctx_compact` / `ctx_build` / `ctx_inject` signatures are unchanged and all new fields are additive.

## Release Highlights

- **Observability you can query**: compaction now records an append-only cost/cache annotation ledger, and a new read-only `claw-ctx cost` command aggregates it by window, compares strategy versions (A/B), and emits JSON or a markdown report.
- **Honest usage numbers**: when the in-process usage ledger misses, the engine falls back to the persisted usage ledger; when neither has data, the cache share is `null` (unknown) rather than a fabricated 0.
- **Host contract made explicit**: the engine now declares its transcript semantics and implements `commitTurn` with durable, per-session idempotency.
- **Release pipeline guards**: CJK preflight before `gh release create`, the post-publish gate kept as a backstop, and `--generate-notes` is forbidden in favor of `--notes-file`.

## Key Changes

### Cost and cache annotation ledger (`claw-ctx cost`)

A successful compaction appends one JSONL annotation to `<workspace>/.claw-ctx/cost-annotations.jsonl`. The ledger is append-only, fail-open, and isolated from session history. The read-only `claw-ctx cost` command supports window aggregation, strategy-version A/B comparison, `--json` output, and a markdown report.

### Persisted usage fallback

When the in-process usage ledger has no entry, the engine reads the session's latest usage from the persisted `<workspace>/.claw-ctx/usage-ledger.jsonl` (read-only, fail-open). Priority is: memory, then persisted JSONL, then `null`. The module header now documents the source priority, the host persistence contract, and the release-notes wording constraint: this release must not claim cache legibility delivered while the data plane is empty.

### Transcript semantics and idempotent turn commits

- `INFO.transcriptSemantics` declares `currentTurnFence: before-current-turn-entry-v1` and `turnAdvancementIdempotency: atomic-idempotent-v1`.
- `TurnCommitLedger` stores per-session JSONL under `<workspace>/.claw-ctx/turn-commits/` with append plus fsync, torn-tail tolerance, empty-key fail-fast, and per-session idempotency scope.
- `ClawContextEngine.commitTurn(params)` returns `committed` or `duplicate` and accepts the full host parameter shape (closes #18).

### Stage-gate dispatch evidence

The stage-gate client-mode audit for main-branch pushes now requires a release dispatch record. The dispatch check follows the seat rather than the persona: `Edith` (current ReleaseAgent) and `Karen` (legacy/historical records) are accepted.

### Release pipeline guards

- CJK preflight runs before `gh release create` (OBS-2); the post-create gate remains a backstop.
- `--generate-notes` is forbidden; `--notes-file` is mandatory.
- Release approval requires a dedicated approval section containing a line-initial `**RELEASE APPROVED**` marker.

## Bug Fixes

- **CLI time bounds**: missing, empty, and bare-flag values for `--from`/`--to` now produce distinct invalid-value errors and exit code 2.
- **Ledger validation**: `readCostAnnotations` validates `cachedTokenShare` in `[0,1]` or `null` and the `triggerReason` enum; out-of-range rows are counted as bad lines.
- **Symlink-safe main guard**: `invokedDirectly()` now resolves both sides through `realpath`, fixing silent no-ops for npm bin, npx, and global installations.
- **Cache share wiring**: `cachedTokenShare` is computed from the real usage ledger as `cacheRead / (input + cacheRead + cacheCreation)`; it is `null` when no usage is reported, and average/delta calculations skip unknown rows.
- **Knowledge-graph entity boundaries**: multi-word entity merging now treats conjunctions (`and`/`or`/`but`) as boundaries, so an object no longer swallows the next clause's subject.
- **Relation quality filter**: the copula relation pattern was removed so question words no longer enter the knowledge graph.
- **Memory hit score**: the score is read from `metadata.retention`; `confidenceReport` now exposes gate-drop diagnostics.
- **Release CJK check**: parsing uses the `gh` `name` field, and the mock field whitelist is hardened.

## CI

- Required branch-protection contexts are `lint`, `test`, `build`, so they no longer drift when the Node matrix changes.
