## 目标

把压缩阈值从「静态 compressionThreshold」升级为「按任务复杂度动态估计的 MECW（最大有效上下文窗口）」。

## 现状（已确认）

- `model-profile.ts`：每个模型已有静态 `context.maxTokens` + `context.effectiveWindowRatio`（0.8~0.9）。
- `model-aware-optimizer.ts`：`getOptimizationHint(modelId)` 已返回 `maxContextTokens` + `effectiveWindowRatio`。
- `ContextTaskType`（4 类）+ `ContextTaskDetector.detectTaskType(query)` 已存在。
- `ProactiveCompactionController.shouldCompact` 当前 threshold 用静态 `compressionThreshold`，**未接 MECW**。

## 核心设计：MECW 公式

```
MECW(modelId, taskType) = maxContextTokens × effectiveWindowRatio × complexityFactor(taskType)
```

- `maxContextTokens`、`effectiveWindowRatio`：复用现有 model-profile（静态）。
- `complexityFactor(taskType)`：**新增**，v6.5.0 核心增量（相对缩放，非绝对值）。

### complexityFactor 初始值（Peter 已确认 A：我给初始值）

| ContextTaskType | complexityFactor | 语义 |
|-----------------|:---:|------|
| SIMPLE_LOOKUP | 1.0 | 简单任务可用满有效窗口 |
| MULTI_LOOKUP | 0.8 | 多步查询略降有效窗口 |
| SUMMARIZATION | 0.7 | 摘要任务需预留输出空间 |
| COMPLEX_REASONING | 0.6 | 复杂推理有效窗口显著缩小（论文结论） |

> 方向与论文一致：复杂任务 → 小 MECW；简单任务 → 大 MECW。
> 因子做成**可配置**，v6.6.0 将在此基础上做自适应调优。

## 模块设计

### 1. 新增 `src/mecw/MecwEstimator.ts`

```typescript
export interface MecwEstimate {
  modelId: string;
  taskType: ContextTaskType;
  maxContextTokens: number;       // 来自 model-profile
  effectiveWindowRatio: number;   // 来自 model-profile
  complexityFactor: number;       // 来自 complexityFactor 表
  mecwTokens: number;             // = 三者乘积（向下取整）
}

export class MecwEstimator {
  constructor(optimizer?: ModelAwareOptimizer, factors?: Partial<Record<ContextTaskType, number>>) {}
  estimateMecw(modelId: string, taskType: ContextTaskType): MecwEstimate;
  getComplexityFactor(taskType: ContextTaskType): number;
  getFactors(): Readonly<Record<ContextTaskType, number>>;
}
```

- 复用 `ModelAwareOptimizer.getOptimizationHint(modelId)` 取 maxContextTokens / effectiveWindowRatio。
- 默认 `DEFAULT_COMPLEXITY_FACTORS` 如上表，可构造时覆盖。

### 2. 打通 `ProactiveCompactionController`

- `shouldCompact(sessionId, modelId, currentTokens, taskType?)` 新增可选 `taskType` 参数。
- threshold 计算改为：
  - 若传入 `taskType` → `threshold = MecwEstimator.estimateMecw(modelId, taskType).mecwTokens`
  - 若未传 → 回退现有静态 `compressionThreshold` 逻辑（向后兼容）
- 其余逻辑（cooldown / limit / minTokens）保持不变。
- 新增 `shouldCompactMecw(sessionId, modelId, currentTokens, taskType)` 便捷方法（或直接扩展 shouldCompact 签名，任选，需在报告说明）。

### 3. claw-mem 集成（压缩前 flush）

- 在 `compact` 触发前调用 claw-mem 的 memory flush（保留重要记忆）。
- 参照现有 claw-mem 集成方式（若已有 memory bridge/接口则复用；否则新增一个轻量 flush 接口，claw-mem 不可用时优雅降级）。
