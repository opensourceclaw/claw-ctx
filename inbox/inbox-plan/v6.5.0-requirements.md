## 背景

claw-ctx v6.4.0 已注册 3 个工具（ctx_compact/ctx_build/ctx_inject），可被 OpenClaw 调用。但**压缩阈值是静态的**——使用固定的 `compressionThreshold`（如 deepseek-v3=96000），未考虑「任务复杂度」对有效上下文窗口的影响。

## 研究依据（arXiv:2509.21361v2）

「最大有效上下文窗口（Maximum Effective Context Window, MECW）」研究表明：模型的有效上下文窗口**远低于标称窗口**，且**随任务复杂度变化**——复杂推理任务的有效窗口显著小于简单查找任务。

## 问题陈述（Problem Statement）

1. **阈值静态**：`ProactiveCompactionController` 用固定 `compressionThreshold`，不区分简单/复杂任务。
2. **未利用 MECW**：已有的 `effectiveWindowRatio`（model-profile 静态值）未与任务复杂度结合，压缩触发点要么过早（浪费）、要么过晚（上下文过长导致质量劣化）。
3. **缺涨前 flush**：压缩前未 flush 重要记忆到 claw-mem，可能丢失跨压缩的重要上下文。

## 目标（Goals）与 非目标（Non-Goals）

### 目标
1. 实现 MECW 估计：`MECW = maxContextTokens × effectiveWindowRatio × complexityFactor(taskType)`。
2. 压缩阈值自适应 MECW（按任务复杂度），保证复杂任务在其有效窗口内触发压缩。
3. claw-mem 压缩前 flush（保留重要记忆）。

### 非目标（本次不做，留后续）
- 阈值「学习式自适应」（v6.6.0 范围）。
- 上下文效率指标导出到 claw-obs（v6.6.0 范围）。
- 任务类型探测的 ML 模型（本次复用 keyword 探测）。

## 关键需求（Functional Requirements）

| # | 需求 | 优先级 |
|---|------|:---:|
| FR-1 | `MecwEstimator` 按公式计算 MECW | P0 |
| FR-2 | 4 类 complexityFactor 可配置（SIMPLE 1.0 / MULTI 0.8 / SUMMARY 0.7 / COMPLEX 0.6） | P0 |
| FR-3 | `ProactiveCompactionController` 接入 MECW，未传 taskType 时向后兼容 | P0 |
| FR-4 | 压缩前 claw-mem flush，不可用时优雅降级 | P1 |

## 非功能需求（Non-Functional）

- 向后兼容：不破坏 v6.4.0 的 3 工具 + compaction 修复。
- 可测试：94+ 测试文件，覆盖公式/factor/backward-compat/降级。
- 可扩展：complexityFactor 做成配置，v6.6.0 可在此基础上自适应。

## 验收标准（Acceptance Criteria）

- [ ] 复杂任务 MECW < 简单任务（论文方向）
- [ ] 阈值按 MECW 触发，未传 taskType 回退静态逻辑
- [ ] claw-mem flush 集成 + 降级
- [ ] 94+ files 全绿，build 零错误
