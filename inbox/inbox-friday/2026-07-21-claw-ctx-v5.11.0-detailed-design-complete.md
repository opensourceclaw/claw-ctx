## 1. 现状分析

### 1.1 压缩管线

```
engine.compactHistory()
  ├─ SemanticCompressor.compress()     // v4.22.0 语义压缩
  │   ├─ scoreImportance()             // 启发式打分（code/decision/entity/question/duplicate）

  │   └─ buildSummary()                // 模板化摘要

```

### 1.2 已识别问题

| ID | 类型 | 位置 | 严重度 |
|----|------|------|--------|
| **L1** | 内存泄漏 | `engine.ts:259` `_memorySearchCache` 无清理 | **P0** |
| **L2** | 边界 bug | `semantic-compressor.ts:211` `compress()` 对 `messages.length=0` 无检查 | P1 |
| **L3** | 类型推断 | `semantic-compressor.ts:76` `extractText()` 对嵌套 `tool_use`/`tool_result` 丢内容 | P1 |
| **L4** | 性能 | `semantic-compressor.ts:130` Jaccard 重复检测为 O(n×k)，k=10 | P2 |
| **L5** | 配置僵化 | `semantic-compressor.ts:96` `minKeep=20` 硬编码 | P2 |
| **L6** | 缓存无界 | `_memorySearchCache` 用 `sessionId` 作 key，无 LRU | P0 |

### 1.3 内存泄漏详细定位

`_memorySearchCache` (engine.ts:259) 与 `_rlGovernanceCache`、`_crossDomainCache` 形成对比：

| 缓存 | key | TTL | 大小限制 | 清理策略 |
|------|-----|-----|---------|---------|
| `_memorySearchCache` | `sessionId` | 30s（懒过期） | ❌ 无 | ❌ 无清理代码 |
| `_rlGovernanceCache` | `sessionId` | 无 | ✅ size ≥ 10 LRU | ✅ 见 engine.ts:1413-1430 |
| `_crossDomainCache` | `cacheKey` | 无 | ✅ size ≥ 10 LRU | ✅ 见 engine.ts:1462-1479 |

**长会话场景**：每创建一个新 sessionId，`_memorySearchCache` 累加一项，永不释放。`_rlGovernanceCache` 限制为 10 项，所以 `_memorySearchCache` 的泄漏被掩盖。

## 3. 详细设计

### 3.1 优化 SemanticCompressor（压缩算法）

**文件**: `src/semantic-compressor.ts`

#### 3.1.1 可配置 minKeep

```typescript
export interface SemanticCompressorConfig {
  minKeep?: number;           // 默认 20
  duplicateWindowSize?: number;  // 默认 10
  duplicateThreshold?: number;   // 默认 0.7（Jaccard）
}

export class SemanticCompressor {
  private config: Required<SemanticCompressorConfig>;

  constructor(config?: SemanticCompressorConfig) {
    this.config = {
      minKeep: config?.minKeep ?? 20,
      duplicateWindowSize: config?.duplicateWindowSize ?? 10,
      duplicateThreshold: config?.duplicateThreshold ?? 0.7,
    };
  }
}
```

**收益**：L5 修复；不同场景（短会话/长会话）可调；可被测试覆盖。

#### 3.1.3 extractText 增强嵌套结构处理

```typescript
function extractText(msg: any): string {
  if (!msg) return "";
  const c = msg.content;
  if (typeof c === "string") return c;
  if (Array.isArray(c)) {
    return c.map((b: any) => {
      if (typeof b === "string") return b;
      if (b?.text) return b.text;
      if (b?.thinking) return b.thinking;
      // L3: 嵌套 tool_use / tool_result
      if (b?.type === "tool_use") return JSON.stringify({ tool: b.name, input: b.input });
      if (b?.type === "tool_result") {
        const inner = Array.isArray(b.content) ? b.content.map((x: any) => x?.text ?? "").join("") : String(b.content ?? "");
        return `[tool_result: ${inner}]`;
      }
      return "";
    }).join(" ").trim();
  }
  return String(c ?? "");
}
```

#### 3.1.4 Jaccard 增量计算（L4 优化）

当前实现：每条消息对前 10 条都做一次完整 Jaccard（每条 O(n) Set 构建）。

优化：滑动窗口内复用前一条的词集，避免重复分词：

```typescript
scoreImportance(messages) {
  const window = new Map<number, Set<string>>(); // index -> wordSet

  for (let i = 0; i < texts.length; i++) {
    const words = new Set(texts[i].text.toLowerCase().split(/\s+/).filter(w => w.length > 3));
    window.set(i, words);
    // 滑出窗口前缘
    if (i > this.config.duplicateWindowSize) {
      window.delete(i - this.config.duplicateWindowSize - 1);
    }
    // 重复检测
    for (let j = Math.max(0, i - this.config.duplicateWindowSize); j < i; j++) {
      const prev = window.get(j);
      if (prev && jaccardSetSimilarity(words, prev) > this.config.duplicateThreshold) {
        score += DUPLICATE_PENALTY;
        factors.push("duplicate");
        break;
      }
    }
  }
}
```

`jaccardSetSimilarity` 直接接收 Set，避免重复构造。

### 3.2 引擎集成优化

**文件**: `src/engine.ts`

#### 3.2.1 修复 `_memorySearchCache` 泄漏（L1 + L6）

引入统一 LRU 包装，所有三个 session-level 缓存共用：

**新文件**: `src/lru-cache.ts`

```typescript
export class LRUCache<K, V extends { ts: number }> {
  constructor(private maxSize: number, private ttlMs?: number) {}

  get(key: K): V | undefined { /* 检查 TTL，命中则更新 LRU 顺序 */ }
  set(key: K, value: V): void { /* 超容量时淘汰最旧 */ }
  delete(key: K): void;
  get size(): number;
  /** 清理所有过期项（按 TTL） */
  prune(): number;
}
```

**engine.ts 改动**：

```typescript
// v5.11.0: 统一 LRU，size=32，TTL=30s（_memorySearchCache 原有 TTL）
private _memorySearchCache = new LRUCache<string, { query: string; block: string; ts: number }>(32, 30_000);
private _rlGovernanceCache = new LRUCache<string, { result: string[]; ts: number }>(10);
private _crossDomainCache = new LRUCache<string, { /* ... */ ts: number; /* ... */ }>(10);
```

engine.ts:1370、1402、1450 的访问改用 `.get()` / `.set()`，LRU 内部处理过期和淘汰。

**内存收益**：
- `_memorySearchCache` 从无界 -> 32 项上限
- 长会话（1000 轮）预期减少堆占用约 18%（主要来自 sessionId → block 字符串的释放）
- 加上 token 优化（3.3），合计可达 20% 目标

#### 3.2.2 引入 session 清理钩子

```typescript
/** v5.11.0: 显式清理 session 资源 */
closeSession(sessionId: string): void {
  this._memorySearchCache.delete(sessionId);
  this._rlGovernanceCache.delete(sessionId);
  // _crossDomainCache key 不是 sessionId，但可以 prune()
  this._crossDomainCache.prune();
  this.logger.debug?.(`[claw-ctx] session ${sessionId} resources released`);
}
```

让 OpenClaw 在 session 结束时调用，主动释放。

### 3.3 Token 数量减少（无信息损失）

#### 3.3.1 摘要模板精简

当前 `buildSummary`（semantic-compressor.ts:196）输出固定格式，含空字段占位：

```
[Compacted History - 0 earlier messages summarized]
Topics: general discussion

Referenced entities:

Continue with the current task using the remaining recent context below.
```

**问题**：即使没有 decisions/entities 仍占行。

优化：

```typescript
buildSummary(messages, count, decisions, entities, topics): string {
  const parts: string[] = [`[Compacted ${count} msgs]`];
  if (topics.length > 0) parts.push(`topics: ${topics.join(",")}`);
  if (decisions.length > 0) parts.push(`decisions: ${decisions.slice(0, 5).join(";")}`);
  if (entities.length > 0) parts.push(`entities: ${entities.slice(0, 8).join(",")}`);
  return parts.join(" | ");
}
```

**收益**：摘要平均从 4 行 ~80 tokens -> 1 行 ~25 tokens。压缩后保留消息数不变，但摘要本身减少约 55 tokens。

#### 3.3.2 重复消息合并（可选，需 Peter 批准）

当前重复消息只是打分扣分但仍保留。可在 `compress()` 中加入"合并"策略：

```typescript
// 标记为 duplicate 且 score < threshold 的消息，合并到首条
const merged = new Set<number>();
for (const idx of removedIndices) { /* ... */ }
```

**风险**：可能丢失时间序列信息。**默认关闭**，通过 config 开启。

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| LRU 淘汰策略影响缓存命中率 | maxSize=32 远大于原 10，命中率应上升；如下降可调 |
| 摘要模板变更影响下游解析 | 摘要本身是自然语言注入 prompt，无机器解析依赖 |
| 嵌套 tool_use 序列化增加 token | 仅在 extractText 内用于打分，不进入实际压缩输出 |
| extractText 行为变化影响现有测试 | 现有测试只覆盖 string content，新行为是严格增强 |
