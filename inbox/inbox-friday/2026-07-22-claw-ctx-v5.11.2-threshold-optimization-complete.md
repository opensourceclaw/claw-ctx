## TL;DR

接续 v5.11.1 自动压缩修复，本次完成两项优化：
1. **压缩阈值 85% -> 75%** - 对齐业界通用的主动压缩比例，为响应留出更多 headroom
2. **删除 OpenClaw `agents.defaults.contextTokens: 200000`** - 让 OpenClaw 按模型自有 `contextWindow` 计算 token 预算，DeepSeek 1M 窗口可真正用满

---

## 1. 背景

### 1.1 v5.11.1 遗留问题

v5.11.1 修复了压缩失效根因（OpenClaw 不读 `autoCompact` 标志，claw-ctx 需自触发），但阈值沿用了原有的 85%，偏保守。

### 1.2 用户新发现

用户观察到 TUI 显示 `volcengine-plan/deepseek-v4-pro | tokens 39k/200k (19%)`，质疑 DeepSeek 1M 窗口为何只显示 200k。

根因：`openclaw.json:291` 配置了 `agents.defaults.contextTokens: 200000`，这是 **agent 级别的 context budget 上限**，会覆盖模型 `contextWindow`。OpenClaw 解析链（`sessions-CRLZ6TJ_.js:295`）：

```
session.contextTokens
  -> agents.defaults.contextTokens (200000, 已删除)
  -> lookupContextTokensForDisplay(model)
  -> null
```

删除全局 `contextTokens` 后，fallback 到模型自有 `contextWindow`。

## 7. 风险与建议

### 7.1 阈值下调的潜在影响

| 维度 | 影响 | 缓解 |
|------|------|------|
| 压缩频率 | 上升（约 +13%）| 预期内，业界主流 |
| 压缩成本 | 每次 compact 需 LLM 调用 | `compactThreshold` 仍由 OpenClaw 传入 |
| 上下文丢失 | 略增（压缩更频繁）| `keepRecentTokens: 20000` 保证近期消息 |
| 缓存命中 | 可能略降（压缩后前缀变化）| DeepSeek prompt cache 命中率需观察 |

### 7.2 1M 窗口解绑的潜在影响

| 维度 | 影响 | 缓解 |
|------|------|------|
| 单 prompt 成本 | 长会话显著上升 | 75% 阈值会主动压缩，避免无限制增长 |
| 首 token 延迟 | 长上下文延迟升高 | DeepSeek prompt cache 缓解 |
| 会话文件大小 | 可能膨胀到几十 MB | `maxActiveTranscriptBytes: "5mb"` 限制 |
| 内存占用 | 上升 | 用户已知情（2026-07-12 日志已讨论） |

### 7.3 建议观察指标

重启 gateway 后建议观察 1-2 天：
- `[claw-ctx] afterTurn: N tokens > M threshold ... triggering self-compaction` 日志频率
- `[claw-ctx] COMPACT: X msgs -> Y msgs` 压缩效果
- TUI token 使用率变化（应从 `39k/200k (19%)` 变为 `39k/1024k (3%)`）
- DeepSeek API 成本变化
