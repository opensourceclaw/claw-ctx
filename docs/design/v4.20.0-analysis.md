## 1. 代码库概览

- **版本**: package.json 4.19.2（index.ts plugin 版本字段 5.1.0 — 不一致）
- **源文件**: 21 个 .ts 文件，核心 engine.ts 1165 行
- **测试**: 21 个测试文件，覆盖率阈值 80%
- **依赖**: 仅 `js-tiktoken`（唯一运行时依赖），claw-mem 为可选依赖
- **插件类型**: OpenClaw `context-engine` kind，通过 `api.registerContextEngine()` 注册

## 2. 现有能力对照任务需求

### A. Gateway 深度集成 — 现状

claw-ctx **已注册为 context-engine 插件**，实现了完整的 OpenClaw context engine 契约：
- `bootstrap()` / `ingest()` / `assemble()` / `compact()` / `maintain()` / `afterTurn()`
- `prepareSubagentSpawn()` / `onSubagentEnded()` / `dispose()`

**差距**: 未验证 Gateway 实际调用这些方法，未测试与现有 Hook 机制的共存。

### B. Drift 自动化响应 — 现状

- `DriftDetector` 已实现，支持 drift score 计算（滑动窗口 + TF 关键词 + cosine 相似度）
- 三级告警: low(0.3) / medium(0.5) / high(0.7)
- `suggestActions()` 已建议 compact/new_session — **但仅在 system prompt 中注入建议，不执行自动操作**
- `DriftBudgetLinker` 类已存在但 **从未在 engine.ts 中实例化或使用**

**差距**: 零自动化。没有 auto-compact 触发逻辑，没有 auto-new-session 信号。

### C. Cross-session 记忆复用 — 现状

- `SessionStateExtractor`: 单 session 内状态提取（entities/decisions/topics/actions）
- `LongTermDependencyTracker`: 支持跨 session 实体关系查询
- `_loadPreviousSessionContext()`: bootstrap 时加载上一 session summary
- `_storeSessionSummary()`: afterTurn 时存储 session summary

**差距**: 缺少跨 session 完整记忆拉取管道，缺少 Relevance Scorer 过滤低相关历史。

## 3. 架构问题

| 问题 | 严重度 | 说明 |
|------|--------|------|
| engine.ts 过大 | 中 | 1165 行，职责过多 |
| 版本号不一致 | 高 | package.json=4.19.2, plugin=5.1.0, CHANGELOG 停在 4.9.0 |
| DriftBudgetLinker 未集成 | 中 | 类存在但未使用 |
| Token 估算不统一 | 低 | injectors 用 char/3.5，engine 用 tiktoken |

## 4. 结论

三个 P0/P1/P2 任务均可实现，基础架构已就绪：
- **A (Gateway)**: 主要是验证 + 配置工作，非代码开发
- **B (Drift)**: 在 engine.ts 中集成 DriftDetector 的 auto-response 逻辑
- **C (Cross-session)**: 增强 SessionStateExtractor + 新增 RelevanceScorer

进入 Phase 2 设计。
