## 1. Background

### Current Implementation (v4.20.0)
- **Token-based truncation**: Keeps recent N messages to stay under token budget
- **Keyword extraction**: Basic keyword matching from message content
- **Limitations**:
  - Cannot distinguish important vs unimportant messages
  - Loses context in the middle of conversation
  - Summary is generic, not content-aware

### Problem Statement
```
Current: [User: A] → [Assistant: B] → [User: C] → [Assistant: D]
            ↓ compress (keep last 20 messages)
Result:   Loses A/B if conversation is long, middle context is lost
```

---

## 2. Target State

### v4.22.0: Semantic Compression

| Aspect | Current (v4.20) | Target (v4.22) |
|--------|-----------------|----------------|
| **Selection** | Token count based | Semantic importance based |
| **Middle content** | Discarded | Preserved via summary |
| **Key info** | Keywords only | Entities, decisions, code snippets |
| **Summary quality** | Generic template | Content-specific |

## 3. Design

### 3.1 New Module: SemanticCompressor

```
src/
├── semantic-compressor.ts   # NEW: Core compression logic
```

**Responsibilities**:
1. Analyze message importance (role, content type, entities)
2. Select messages to keep based on importance score
3. Generate content-aware summary of removed messages
4. Preserve critical context (decisions, code, entity references)

### 3.2 Importance Scoring

```typescript
interface MessageImportance {
  score: number;           // 0-100
  reason: string;          // why this message matters
  preserveLevel: 'full' | 'summary' | 'discard';
}
```

**Scoring factors**:
| Factor | Weight | Description |
|--------|--------|-------------|
| Contains code | +30 | Code snippets are high value |
| Contains entities | +20 | Names, numbers, IDs |
| Decision content | +25 | "决定", "选择", "approved" |
| Question | +15 | User questions important |
| System message | +10 | Configuration context |
| Duplicate content | -20 | Repeated messages |
| Generic greeting | -30 | "hello", "hi" |

### 3.3 Compression Strategy

```
Input: [M1, M2, M3, ... M100] (over token budget)
  ↓
1. Calculate importance for each message
2. Keep: Top N high-importance messages + Recent 10 messages
3. Summarize: Remaining middle messages as semantic summary
  ↓
Output: [Summary(M1-M80)] + [M90, M91, ... M100]
```

## 4. Integration

### 4.1 Changes to engine.ts

```typescript
// Add SemanticCompressor
import { SemanticCompressor } from "./semantic-compressor.js";

// In constructor
this._semanticCompressor = new SemanticCompressor();

// Modify _executeCompaction
async _executeCompaction(sessionFile: string, targetTokens: number) {
  // Option A: Use semantic compression
  const result = await this._semanticCompressor.compress(
    entries, 
    targetTokens,
    this.config.compressionStrategy ?? 'semantic' // or 'legacy'
  );
}
```

### 4.2 Config Addition

```typescript
interface ClawCtxConfig {
  // ... existing
  compressionStrategy?: 'semantic' | 'legacy';
  semanticCompressOptions?: {
    keepRecentMessages: number;  // default: 10
    keepTopImports: number;      // default: 15
    preserveCodeSnippets: boolean; // default: true
  };
}
```
